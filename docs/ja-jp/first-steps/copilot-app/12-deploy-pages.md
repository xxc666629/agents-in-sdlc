GitHub Pages にデプロイして、Space Quiz を公開しましょう。Copilot はワークフローを準備し、デプロイをガイドできますが、変更のレビューとサイトが公開されたことの確認は自分で行います。

このレッスンでは、次の作業を行います。

- Copilot に GitHub Pages のデプロイ構成を依頼します。
- マージする前にワークフローとプル リクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰でも簡単に試せる方法が必要です。GitHub Pages を使って単一ファイルのサイトを公開すれば、サーバーやランタイム依存関係を追加せずに公開 URL からアクセスできます。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更でプル リクエストを作成し、必須チェックに合格したらマージしてください。デプロイが成功するまで監視し、ライブ Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、何を承認または実行すればよいか正確に教えてください。サイトが公開されるまで成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトは、エージェントにプル リクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。進める前に、diff、デプロイ権限、GitHub の承認プロンプトを確認してください。

## ワークフローをレビューしてデプロイを確認する

1. リポジトリに README がない場合に限り、README が追加されたことを確認します。
2. ワークフローのビルドとデプロイのステップを含め、プル リクエストの変更をレビューします。
3. 必須のプル リクエスト チェックに合格してからマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages を有効にしたりプル リクエストをマージしたりできない場合は、提示された具体的な手順に従います。デプロイが成功し、ライブ サイトが読み込まれるまでタスクを完了扱いにしないでください。
